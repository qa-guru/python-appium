Практика · локальная сессия

Android: минимальные типизированные options

from appium import webdriver
from appium.options.android import UiAutomator2Options

options = UiAutomator2Options()
options.platform_name = "Android"
options.automation_name = "UiAutomator2"
options.udid = device_udid
options.app = apk_path
options.no_reset = False

driver = webdriver.Remote(
    appium_url, options=options
)

appium_url — выбранный учебный сервер.

device_udid — конкретный serial.

apk_path — файл на машине Appium Server.

Если задаём package/activity вручную, они должны соответствовать именно этому APK.
Это учебный пример расширения локальных options, не утверждение о готовом UDID в проекте. Типизированные options создают W3C capabilities. Не копируйте org.wikipedia.alpha для stable org.wikipedia. Автоопределение из APK часто достаточно; ручные activity/package добавляются только по проверенным данным.

Allure · live artifacts

Screenshot и page source снимаем до quit()

allure.attach(
    driver.get_screenshot_as_png(),
    name="Screenshot",
    attachment_type=allure.attachment_type.PNG,
)

allure.attach(
    driver.page_source,
    name="Page source",
    attachment_type=allure.attachment_type.XML,
)

Два разных вопроса

Screenshot: что было видно?

Page source: какие элементы и атрибуты были доступны?

XML не заменяет картинку. Картинка не заменяет дерево элементов.
Снимок при падении нужен раньше, чем финальный screenshot teardown: после очистки экран может измениться. XML может содержать данные пользователя, поэтому не используйте чужие учётки и не прикладывайте секреты. Для карточки ошибки показывайте названия артефактов, которые различают failing state и final state.
Allure · lifecycle

Сессия завершается при любом исходе теста

@pytest.fixture
def driver(config):
    drv = create_driver(config)
    session_id = drv.session_id
    try:
        yield drv
    finally:
        try:
            attach.screenshot(drv)
            attach.page_source(drv)
        finally:
            drv.quit()
        attach.video(config, session_id)
  • Запоминаем session_id заранее.
  • Live-аттачи — пока драйвер жив.
  • quit() — гарантированный cleanup.
  • Remote video — после quit.
Контракт helpers: ошибки аттачей диагностируются, но не маскируют исходный сбой теста.
Эскиз демонстрирует границы, а не исчерпывающую реализацию. attach.screenshot/page_source/video должны сами обрабатывать только свои artifact-ошибки; иначе exception может прервать следующий аттач. Setup после создания драйвера также требует cleanup при падении до yield. Cleanup-failure нельзя просто скрывать: отчёт должен показывать незавершённую сессию как инфраструктурную проблему.
Allure · failure state

Screenshot в момент падения, не после reset

@pytest.hookimpl(hookwrapper=True)
def pytest_runtest_makereport(item, call):
    outcome = yield
    report = outcome.get_result()
    if report.when != "call" or not report.failed:
        return
    drv = item.funcargs.get("driver")
    if drv is not None:
        attach.screenshot(
            drv, "screenshot on failure"
        )

Hook выполняется после тестового вызова, до teardown фикстуры.

Для падения setup нужна отдельная точка сбора в setup-ветке фикстуры.

Проверяем контролируемым падением: исходная ошибка сохранена, аттачи есть, сессия закрыта.
Этот call-failure hook уже есть в локальной ветке. Сверьте его с текущим кодом, не добавляйте второй. attach.screenshot должен быть best-effort, иначе ошибка артефакта станет ошибкой hook. Не оставляйте намеренно падающий тест в финальном наборе; используйте существующий runner и согласованный временный сценарий.

iOS · форматы

Simulator

  • Сборка для iphonesimulator.
  • .app или архив с .app.
  • Подходящая архитектура host.
  • Не нужен платный Developer account.

Диагностика

Ищем сбой на нужном участке цепочки

СимптомПроверяем
Не создаётся сессияEndpoint/base path, driver, platform, capabilities, доступ
adb: unauthorized / offlineДоверие на телефоне, подключение, полный boot
Приложение не установилосьФайл на сервере, URL с фермы, ABI, SDK, подпись
Element not foundPNG + XML, onboarding, локаль, версия приложения
xcodebuild: 65 / 70WDA signing/provisioning, Xcode/OS configuration
Нет remote videoenableVideo, session_id, quit, публикация и авторизация
Начинаем с минимального разрешённого probe фактической границы. Если нет доступа или подписанной сборки — BLOCKED, а не ремонт инфраструктуры. Не добавляем автоперезапуски, retries и массовые cleanup-команды. Screenshot системного диалога ANR объясняет проблему приложения, но постоянное нажатие Wait не считается исправлением причины.

Checklist преподавателя

Приложение и устройства
